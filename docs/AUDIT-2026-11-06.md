## C. Red team / fuzz

- `parseChunkIndex` fuzz: empty, negative, float, hex, `1e3`, whitespace, `NaN`,
  `Infinity`, 38-digit overflow, null/undefined/object/array → **all rejected**; valid
  `0`/`5`/`chunkCount-1` accepted; out-of-range blocked. No bypass.
- Allocator red-team: **200,000** randomized `lease/leaseBatch/complete/release/
  importDone/reclaimExpired` ops across 3 devices → **0 invariant violations**: a chunk is
  never simultaneously `done` and `active`, no index ever out of range, no duplicate index
  within a batch, never leases an already-done chunk.
- `--serve` parser: malformed stdin line → `ERR parse` and continue (no crash); progress
  loader skips non-numeric lines.
- Not executed here: live SSRF/CSRF/replay against a running Worker (no reachable
  deployment); GPU-disconnect / VRAM-exhaustion / process-kill mid-compute (no GPU).

## F. Cryptographic correctness

- CUDA self-test ground-truth vectors (keys 0x1/0x3/0x15/0x202 → hash160) **independently
  reproduced** by the TS core reference; key 0x1 → `751e76…33bd6` is the publicly known
  hash160 of private key 1, closing the trust chain.
- CUDA host-models verified earlier this project vs independent references: 512-bit product
  (200k), field `mod_mul` vs reference incl. edges (300k), `mod_inv` chain + a·inv=1,
  dedicated `sqr` == mul(a,a) (500k), comb `scalar_mul` == double-and-add (30k),
  SHA-256/RIPEMD-160/hash160 vs reference + KATs (480k), `addKeyOffset` vs bignum (2M) —
  **0 mismatches**.
- CPU/GPU consistency: the CUDA self-test compares GPU output to the same vectors the TS
  reference produces; on a real GPU a mismatch returns exit 2 and refuses to search.
- #72 target `bf7413…54adb` identical across core / worker / Go / CUDA.
